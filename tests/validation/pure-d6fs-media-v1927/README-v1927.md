# D6FS PURE physical identity, v1927

    DAIMOS_REPO=$HOME/git/DAIMOS make test-pure-d6fs-media-v1927

The native gate links the original provider dispatch, selected-header
proof, mount publication/reader retirement, fs_backing_read and clean
BCACHE invalidation assembly. It controls physical transfer, MM and VFS
publication boundaries. Twelve faults (both UUID halves, transfer refusal,
false-success with stale workspace, magic, sequence, state and five
geometry fields) are refused; each retry with the original superblock
succeeds. Mount capture, refused reader free, successful retirement and
failed mount rollback preserve the independent root's state. Four
executed unsafe variants fail native assertions at 0101, 0114, 0103 and
0001 octal. This is not a whole-guest disk replacement experiment.

The formatter gate builds the actual host mkdsk, mkd6fs and d6fsck and
formats two equal-layout images with the same namespace. Both pass
fsck, each A/B superblock pair matches, and their 72-bit identifiers
are distinct. It does not claim retroactive uniqueness of old images.

The existing v1925 reconstruction bridge exercises eight DTFS, eight
D6FS and two TSFS cases at controlled provider boundaries. The v1926
DROP oracle includes missing D6FS identity and failed-proof cases.
Older dispatch, multimount, reader-slab and remount fixtures were
updated for the new private operation and mount header capture.
