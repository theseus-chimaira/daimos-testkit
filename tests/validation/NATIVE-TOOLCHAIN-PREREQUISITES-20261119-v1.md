# Native guest toolchain prerequisites - 2026-11-19 v1

The relocated 25 suites are independently selectable, not a standalone
self-contained regression matrix. They consume staged DAIMOS boot images,
accepted native toolchain binaries and/or explicit operator-provided
boot/PTY artifacts. The shell registry's `ready` status only means that
all suite files exist; it does not imply these prerequisites exist.

Initial inspection of the current Termux environment finds the installed
`$PDP10_PREFIX/bin/{pdp6,csix,das,dlink,s6text,sixmd-check}` and sibling
`DAIMOS`, `kcc`, `das` and `daimos-tools` repositories. `DAIMOS_REPO` is
not exported by default; set it to `$HOME/git/DAIMOS` when invoking
native suites. The default TMPDIR is under the Termux prefix; do not
assume artifacts in `$HOME/tmp` are equivalent to those in `$TMPDIR`.

The native KCC phase-isolation and exit-status suites require
`KPARSE_BOOT` and `KPARSE_PTY`. Progress samplers require `SAMPLE_BOOT`
and `SAMPLE_PTY`. Several DAS/DLINK suites require a separately accepted
native DAS/KCC build (`NATIVE_DAS_BUILD`, `V1405_NATIVE_DAS`,
`V1411_NATIVE_DAS`, `V1404_NATIVE_DAS`, `V1403_DAS_NATIVE`,
`V1403_KCC_NATIVE`). These variables are not generated by the runner.

The full native chain depends on accepted `d6codec-fullboot-v1370`,
`d6codec-fulldist-v1371`, `kcc-kgen-stack-lifetime-v1401-testkit`,
`das-native-ascii7-v1402-testkit-r2`, and subsequent native DLINK/DAS
artifacts. At the start of this inspection, the first two TMPDIR
locations existed, but the v1401 and v1403 acceptance directories did
not. Directory existence alone is not a passing acceptance oracle.

The native MAKE dry-run suite still expects the historical literal
`/OPTION/BASE/EXEC/DAS`; current `kcc/daimos.mk` instead sets
`NATIVE_DAS = DAS`. The stale literal oracle has been corrected to expect the
actual `DAS -F -C -O` invocation from the current Makefile. The
object-name and exit-status assertions remain. The guest test still
requires execution before a pass can be claimed.

Do not use `run-all` to paper over missing stage artifacts. Execute each
suite in dependency order, retain reports and failure logs, and record
runtime outcomes separately from the static dispatcher checks.

## First execution attempt (2026-11-19)

Executed the selected `native-kcc-daimos-native-kcc-make-preflight-20261008-v1`
through the new DAIMOS dispatcher, with `DAIMOS_REPO=$HOME/git/DAIMOS`
and the installed `$PDP10_PREFIX`. An outer 180-second wall-clock
limit was imposed for the initial smoke run. The prerequisite DAIMOS
`system/boot/pdp6 image` build was still processing its userland/manual
stage at the limit, so the attempt returned **124 (timed out)** before
the native KCC MAKE probes could start. This is **incomplete**, not a
compiler test failure and not a pass. The temporary build was removed
by the script's normal cleanup. No full guest-native acceptance run was
performed. Future attempts must allocate an appropriately long build
window and capture durable reports, rather than inferring an oracle
result from this timeout.

## Ten-minute preflight and real oracle failure

A 600-second invocation completed in about 223 seconds. Three guest
probes passed; the fourth, `kcc-native-first-object`, failed. A second
600-second run with `KEEP_WORK=1` reproduced the 3 PASS / 1 FAIL
result and retained the SIMH report in the user's TMPDIR. Its
`run/norm.4` proves the issue: `MAKE: DON'T KNOW HOW TO MAKE:
B/CC-CPP-V1.S`, followed by `STATUS:1`. The staged current KCC
`daimos.mk` has `BUILD/CC-CPP.S`, not `B/CC-CPP-V1.S`, and its
aggregate target is `NATIVE`, not `ALL`. The previous `ALL` probe
incorrectly passed merely because `STATUS:1` was expected, even
though native MAKE reported `DON'T KNOW HOW TO MAKE: ALL`.

Both native MAKE test scripts have been updated to request the actual
`NATIVE` and `BUILD/...` targets and to reject `DON'T KNOW HOW TO MAKE`
output. The preflight now also checks the first-object exit status and
build announcement against the real target. These are corrections of
stale test oracles, not changes to DAIMOS or KCC production sources.
The corrected execution result must be reported separately.
