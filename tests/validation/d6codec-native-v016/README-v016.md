# PDP-6 paired-descriptor decoder exhaustive peephole search v016

Isolated testkit research; no DAIMOS/KCORE modification.

Run `python3 search_v016.py` to enumerate the 2^3 combinations of
three independent local assembler rewrites. Each candidate is assembled
with DAS, and its actual 36-bit .text word count obtained with
`pdp10-objdump -h`. The generated `optimizer-results-v016.txt` records all
eight candidate combinations. All eight assemble. They are **not** all
semantically validated merely because assembly succeeds.

The smallest candidates use the `popcount` rewrite, replacing the branch
around the match-counter increment with PDP-6 SKIPGE. This saves exactly
one 36-bit instruction. The chosen `decode_v016.s` measures 98 words,
versus the v015 99-word decoder, with no static data or BSS.

Run `./run-v016.sh` to execute the packed word-reference/zero-run fixture
against `decode_v016.s` in an isolated PDP-6 simulator. That test passes.
No malformed-stream matrix, halfword references, streaming/refill, standard
kernel ABI, or production integration is yet validated. The selected code
remains an experimental limited-function decoder.

A smaller *unsafe* candidate was initially generated by deleting a
required count upper-bound check. That transform was removed from the
search space: size reductions must not weaken stream validation.

This exhaustive search covers only the explicit three local rewrites,
not the global optimum over all assembler programs or instruction layouts.
